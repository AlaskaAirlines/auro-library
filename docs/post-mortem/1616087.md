# AB#1616087

**Scope:** `auro-library` — doc-generation scripts repackaged as pre-compiled bundles. 50 files changed on `cfriedberg/unship-deps`; no consumer-facing API change.

## Executive Summary

`auro-library` sits near the root of the Auro dependency graph — nearly every Auro component depends on it, and every application that uses those components inherits whatever it declares. It was declaring two documentation-authoring tools, **Handlebars** and **markdown-magic**, as things every consumer must install. Those tools are only used when someone generates documentation; they were never needed to run an Auro component in a browser.

The result: every downstream project — and every application built on top of one — silently installed two extra packages and their dependency trees, inflating install size and causing security scanners such as Dependabot to flag build-time tooling as if it were shipped production code.

This change pre-compiles the documentation scripts into a self-contained form that carries those tools inside it. The tools move to development-only status and disappear from every consumer's dependency list. Nothing a consumer does changes: the same commands, at the same file paths, keep working. Upgrading is a version bump.

The same treatment was extended to two further undeclared tools — `glob` and `chalk` — that were being resolved out of consumers' own installs by accident.

## Technical Research Document

[AB#1616087 — TRD: Drop handlebars / markdown-magic as Runtime Dependencies](https://github.com/orgs/AlaskaAirlines/discussions/654)

The TRD establishes the requirement set used below (FR-1–FR-6, NFR-1–NFR-5), rules out relocating the scripts to `auro-cli` and using optional peer dependencies, and specifies the `src/` → `dist/` → shim layout, the esbuild configuration, and the six-test verification plan.

## The Problem

A software package declares two kinds of dependencies: things it needs in order to *run*, which everyone who installs it must also install, and things it needs only while it is being *developed*, which nobody downstream ever sees.

`auro-library` had Handlebars and markdown-magic in the first category. They belong in the second. But they could not simply be moved, because the documentation scripts `auro-library` publishes are shipped as plain, uncompiled source that reaches out for those tools at the moment they run. Reclassifying them without changing how the scripts ship would have converted an oversized install into an outright failure: any component team running documentation generation would have hit a "module not found" error the next time they upgraded.

So the choice was not "move the dependency or don't." It was: find a way to ship the documentation scripts such that they no longer need to reach outside the package at all.

## Root Cause

Three runtime `dependencies` were declared in `package.json`; only `@floating-ui/dom` (consumed by `scripts/runtime/floatingUI.mjs`) was genuinely runtime. `handlebars` and `markdown-magic` were reachable only from the doc-generation entry points.

The reclassification was blocked by the publishing model, not by the classification itself. `auro-library` published the doc-gen entry points as unbundled ESM at `scripts/build/**` and `bin/**`. A consumer's `build:docs` / `build:api` step executes those files directly, so the bare specifiers `import "handlebars"` and `import "markdown-magic"` resolve against the *consumer's* `node_modules`. The published source is the thing that creates the runtime requirement.

Two secondary instances of the same shape were found during implementation:

- **`glob`** — `scripts/build/generateWcaComponent.mjs` imported it bare while it was declared nowhere. It resolved only because host repos happened to have it hoisted, at a deprecated, CVE-flagged `glob@7`.
- **`chalk`** — imported bare by `scripts/utils/logger.mjs`, `auroLibraryUtils.mjs`, `pre-commit.mjs`, and `postinstall.mjs`, also undeclared. These files ship unbundled, so bundling could not reach them.

Two implementation-level causes surfaced inside the bundling work itself:

- `markdown-magic/lib/transforms/index.js` eagerly loads `code.js` → `remoteRequest.js` → `sync-request` → `sync-rpc`, which calls `require.resolve("./worker")` at module load. Inside a bundle that resolves relative to the output file and throws `Cannot find module './worker'` — on every run, not only when a remote transform is used.
- `bin/generateDocs.mjs` and `bin/generateDocs_index.mjs` derived their paths from `import.meta.url` relative to their own location. Emitting them to `dist/bin/` shifted that anchor one level deeper and broke the resolution.

## The Fix

The work on `cfriedberg/unship-deps` (PR [#296](https://github.com/AlaskaAirlines/auro-library/pull/296)) restructures how the doc-gen entry points are published.

**Layout.** Sources move to `src/` (git-tracked, npmignored). `build/bundleDocsScripts.mjs` compiles them with esbuild into `dist/` (gitignored, published). Committed one-line shims reoccupy the original published paths in `scripts/` and `bin/`. The source path and the published path were previously the same path — moving sources to `src/` breaks that collision so the build can write to the path consumers execute without overwriting its own input.

A `package.json` `exports` map was rejected: `README.md` documents direct-path invocation (`node ./node_modules/@aurodesignsystem/auro-library/scripts/build/generateDocs.mjs`), and direct file paths bypass `exports` entirely. A physical file has to be there.

**The bundler** (`build/bundleDocsScripts.mjs`) builds all 10 entry points in one call with:
- `splitting: true` — required, not an optimization. `sharedFileProcessorUtils.mjs` exports a `templateFiller` singleton written by one module and read by another; without splitting each entry point gets its own copy and `values` stays `null`.
- A `createRequire` banner — esbuild's CJS interop emits a `__require` shim that defers to an in-scope `require`; without it, bundled CJS dependencies die on `Dynamic require of "fs"`.
- `alias: { "sync-request": "build/shims/syncRequest.cjs" }` — a 113-line shim reimplementing the only contract `remoteRequest.js` uses (`request(method, url).getBody(enc)`) via `spawnSync(process.execPath, ["-e", …])` wrapping `fetch`. This drops the entire `sync-rpc` / `then-request` tree from the bundle.
- `rmSync(dist)` before every build — content-hashed chunk names meant rebuilds orphaned previous chunks rather than replacing them, and those orphans shipped (13 chunks / 2.7 MB locally, now 7 / 1.6 MB).

**Single source of truth.** `build/entryPoints.mjs` holds `ENTRIES`; the bundler, the generated shims, and the tests all read it. Adding an entry point is one line. `pruneGeneratedShims` deletes files matching `SHIM_MARKER` before regenerating, so dropping an entry point surfaces as a staged deletion rather than as an orphan nothing imports.

**`glob`.** `generateWcaComponent.mjs` moved to `src/build/` and joined the entry points, so `glob` stays a devDependency and gets inlined. It was moved to `glob` v11's promise API in the process, dropping the deprecated `glob@7`.

**`chalk`.** Bundling could not help — the four call sites ship unbundled. `scripts/utils/ansiColors.mjs` (new, zero dependencies, 114 lines) replaces it, implementing only the two forms this package used: `hex(c)(text)` and `hex(c).bold(text)`. Output is byte-identical to chalk, including per-line style reopening, the empty-string short-circuit, and `FORCE_COLOR > NO_COLOR > TERM=dumb > isTTY` precedence.

**Supporting changes.** `prepare` and `prepack` both run `build:bundles`, so a fresh clone and every publish produce bundles automatically. `.npmignore` gains root-anchored `/src/` and `/build/`, plus test-file patterns. `auroLibraryUtils.mjs` gained optional chaining on the `peerDependencies` reads that made `npm run build:docs` exit non-zero in this repo. The `bin/` path anchoring was rewritten to an explicit `packageRoot` (`fileURLToPath(new URL("../../", import.meta.url))`) that resolves identically from `src/bin/` and `dist/bin/`.

**Tests.** 66 new tests across five spec files: `build/__tests__/distBundle.spec.js` (the shim/bundle contract, including "imports nothing outside the Node builtins" and "tracks every shim in git"), `packaging.spec.js` (dependency classification and tarball contents), `syncRequestShim.spec.js`, and golden-value specs for `ansiColors.mjs` and `logger.mjs`.

## Why This Works

**The dependency disappears because the import does.** After bundling, the only bare specifiers surviving into `dist/` are Node builtins — asserted by a real esbuild parse over `dist/` with `external: ["*"]`, plus a narrow pattern for the `__require()` calls the metafile cannot see in ESM output. A parse rather than a regex, because minified bundles contain prose like `from 'BigInt'` inside error strings.

**Backward compatibility is structural, not promised.** The shims occupy the exact paths consumers have always used, so both `import` specifiers and direct-path execution resolve unchanged. `import.meta.url` inside `dist/` still points inside the package, so `getProjectRootPath`'s `split("node_modules")[0]` still finds the consumer's project root.

**Alternatives were rejected on grounds the AC set.** Relocating to `auro-cli` is explicitly deferred by the ticket. Optional peer dependencies violate "Breaking change: None" — every component's `build:api` would break until that repo added the devDeps itself. Adding `glob` back to `dependencies` would have dragged roughly eight transitive packages into every consumer's production tree, undoing the point of the work.

**The invariants are pinned by tests that were verified to fail.** Every claim was mutation-tested rather than trusted green: `splitting: false` fails the singleton test; removing the banner fails the banner test; removing the `sync-request` alias fails two tests; `handlebars` back in `dependencies` fails the dependency test; injecting `import "handlebars"` into `dist/` fails the builtins test; `git rm --cached` on one shim fails the tracking test. On `ansiColors.mjs`, dropping per-line reopening fails 5, losing `FORCE_COLOR` precedence fails 20.

**Byte-identical output was the acceptance bar for correctness.** Generated `README.md`, `demo/index.md` and `demo/api.md` from the built package match published 5.14.1 on an identical fixture, including all 12 `REMOTE:url=` and both `CODE:src=` transforms — exercising the `sync-request` shim in a project with no `sync-rpc` installed. WCA output under `glob` v11 diffs identical to the `glob@7` version.

## Outcome

A project that installs `@aurodesignsystem/auro-library` no longer installs Handlebars or markdown-magic. The same holds when a real consuming component is installed alongside it.

| Scenario | `npm ls handlebars markdown-magic` |
|---|---|
| Before: install `@aurodesignsystem/auro-dropdown` | `handlebars@4.7.9`, `markdown-magic@2.6.1` |
| After: `auro-library` tarball alone | *(empty)* |
| After: `auro-dropdown` + tarball override | *(empty)* |

Installed in a clean project with production dependencies only, the package now brings a **4-package tree, down from 237**. Documentation generation, WCA preparation, and logging all work in that tree with none of the removed tooling present.

The trade-off: the published package itself grows from roughly 75 kB to 331 kB, because the tooling is now carried inside it. Consumers install less overall; the library's own download is larger.

Two side benefits: a deprecated, security-flagged version of `glob` is no longer pulled in, and eight test files that had been leaking into the published package no longer ship.

**This is not yet visible to end users.** The win only materializes when consuming components upgrade — see Ticket Completeness.

## Ticket Completeness

**10 of 12 requirements fully resolved; 1 partial, 1 not resolved.** Both gaps are in verification and rollout, not in the change itself.

### Resolved

- **FR-1 — Removed tooling must not appear in any consumer's dependency tree.** Both packages moved to `devDependencies` and are inlined into `dist/`. Verified in clean projects outside the repo, alone and alongside a real consuming component.
- **FR-2 — `@floating-ui/dom` stays a runtime dependency.** It is now the only entry in `dependencies`.
- **FR-3 — Existing consumer invocations keep working.** Ten committed shims occupy the original published paths; both package-relative import and documented direct-path execution were exercised in a clean install.
- **FR-4 — Generated documentation must be byte-identical.** All three generated files match published 5.14.1 output on an identical fixture.
- **FR-5 — Project-root resolution must survive execution from inside `dist/`.** Confirmed in a synthetic component repo; a path-anchoring regression introduced in the `bin/` entry points was found and fixed during the work.
- **FR-6 — The remote `CODE:src=<url>` transform must keep working.** Preserved through the `sync-request` shim, covered by eight dedicated tests, and exercised end-to-end in a project with no `sync-rpc` installed.
- **NFR-1 — No breaking change.** No API surface changed; the library upgrade itself is a version bump. (See the rollout item below for the constraint this hits at the consumer end.)
- **NFR-2 — Tarball ships `dist/`, not `src/` or `build/`.** Root-anchored `.npmignore` entries, asserted by an `npm pack --dry-run` test.
- **NFR-3 — Fresh clone and release pipeline build automatically; no committed build output.** `prepare` and `prepack` both chain `build:bundles`; `dist/` is gitignored. Verified by deleting all shims and `bin/` entirely and rebuilding.
- **NFR-4 — Git history of moved files preserved.** `git log --follow` traces the moved sources back through the rename.

### Not Resolved / Partial

- **NFR-5 — Existing suites and lint must pass (partial).** Tests pass (vitest and web-test-runner) and `npm run build:docs` now exits zero. `npm run lint` still reports pre-existing errors repo-wide in files this work did not touch; the count went *down* over the course of the change and no new violations were introduced, but the requirement as written ("all pass") is not met.
- **Rollout (TRD §6) — at least one consumer bumped and re-verified: not resolved.** No consumer was updated. Beyond that, the TRD's assumption that consumers can be *patch*-bumped does not hold: every consumer found (`auro-dropdown`, `auro-datepicker`, `auro-combobox`, `auro-select`, `auro-menu`, `auro-checkbox`, `auro-input` on `^3.x`, `auro-radio` on `~2.8.0`) is pinned below `^5`, and a patch bump cannot cross a major. Each needs a **major dependency-range bump to `^5`** before the transitive install actually drops. Note also that `auro-button` — the reproduction case in the original bug report — no longer depends on `auro-library` at all.

### Beyond the ticket

Four items were resolved that the TRD placed out of scope or did not anticipate: `chalk` was eliminated entirely rather than left external (TRD §7 deferred it to a separate ticket); `glob` was unshipped by the same mechanism and moved off a CVE-flagged v7; a pre-existing leak of eight test files into the published tarball was closed; and the unguarded `peerDependencies?.[key].substring(1)` in `auroTemplateFiller.mjs` — which threw when `peerDependencies` existed but the key was missing — picked up the same `?.substring(1) ?? ""` guard already applied in `auroLibraryUtils.mjs`.

## Learnings

- **A package near the root of a dependency graph has no cheap dependencies.** One misclassified entry in `auro-library` multiplied across every Auro component and every application consuming one. Dependency classification deserves more scrutiny the closer a package sits to the root.
- **"Move it to devDependencies" is only a fix if nothing published imports it.** The publishing model — unbundled source at documented paths — is what created the runtime requirement. Reclassification without repackaging converts a bloat problem into an outage.
- **When the source path and the published path are the same path, a build cannot exist.** Separating `src/` (edit here) from `dist/` (generated) from the shim (the stable public path) is what makes bundling possible at all, and what makes "is this file generated?" answerable.
- **Direct file paths bypass `package.json` `exports`.** Any backward-compatibility scheme that relies on `exports` fails for documented `node ./node_modules/…` invocations. A real file must sit at the path.
- **`splitting: true` is a correctness setting when a module exports shared mutable state.** Without it, each entry point gets its own copy of the `templateFiller` singleton and cross-module state silently reads back as `null` — a failure that looks like a data bug, not a build config bug.
- **Bare imports that resolve by accident are latent breakage.** `chalk` and `glob` worked only because host repos happened to have them hoisted. Enumerating *every* bare import across the published tarball and resolving each one against a real consumer tree found what spot-checking would not.
- **Verify tests by breaking the thing they test.** Golden-value and packaging assertions are easy to write vacuously. Every invariant here was confirmed by a deliberate mutation that made it fail, then reverted.
- **Commit type determines whether a fix ships.** `build(deps):` and `chore:` produce no semantic-release release. A dependency fix typed as anything but `fix:`/`feat:` sits unpublished while looking merged.
- **`spawnSync` blocks the caller's event loop.** An in-process HTTP fixture server for the sync-request shim tests deadlocks until timeout; the fixture has to run in its own process.
- **Content-hashed output needs an explicit clean step.** Without `rmSync`, rebuilds accumulate orphaned chunks that no longer have an importer but still ship.

## Iterations That Didn't Work

**Rejected before implementation (TRD §1.3):**

- **Relocate the doc-gen scripts to `auro-cli`.** The acceptance criteria flag these files as eventually moving there, but state it is not currently prioritized.
- **Optional peer dependencies.** Violates "Breaking change: None" — every component's `build:api` would break until each repo independently added the devDeps.
- **A `package.json` `exports` map instead of physical shims.** The README documents direct-path invocation, which bypasses `exports` and would hit unbundled source.

**Tried during implementation and abandoned:**

- **Bundling without `splitting: true`.** Each entry point received its own copy of `sharedFileProcessorUtils.mjs`, so `templateFiller.values` stayed `null`.
- **Bundling without the `createRequire` banner.** Bundled CJS dependencies failed at load with `Dynamic require of "fs" is not supported`.
- **Bundling `sync-request` as-is.** `sync-rpc` calls `require.resolve("./worker")` at module load, which resolves relative to the bundle output and throws. Replaced with a narrow shim rather than a workaround.
- **Adding `glob` back to `dependencies`** to fix the WCA-generation break. Correct in isolation, but it would have pulled roughly eight transitive packages into every consumer's production tree — undoing the branch's purpose. Bundling it instead was the fix.
- **Declaring `chalk` in `dependencies`.** Implemented and committed, then abandoned: it reached the unbundled call sites, but added a runtime dependency to solve a problem the branch existed to remove. Replaced with the zero-dependency `ansiColors.mjs`, and the commit amended so the branch never carries it.
- **Gitignoring the shims, with the build rewriting a marker-delimited block in `.gitignore`.** Worked and was fully tested, but reverted: the shims are the paths the `bin` field and README point at, so hiding them from GitHub and from a fresh clone hid every documented entry point, and having `npm install` mutate a tracked file is a norm the team would have to absorb. Shims are committed instead, with a "do not edit" header and a byte-for-byte drift test.
- **Deriving `bin/` paths from `import.meta.url`.** Correct at `src/bin/`, broken once emitted to `dist/bin/` a level deeper. Replaced with an explicit `packageRoot` anchor that resolves identically from both — which also drops a `.pathname` URL-decoding hazard.
- **Running the sync-request test fixture server in-process.** `spawnSync` blocks its caller's event loop, so the server never responds and the test hangs to a 30-second timeout. Moved to its own process.
- **Typing the commit `build(deps):`.** Produces no semantic-release release, meaning the fix would never reach npm. Retyped `fix(deps):`.

## Known Residuals

- `docs/partials/generateWcaComponent.md` documents the script at `scripts/generateWcaComponent.mjs` (missing the `build/` segment). Its second example points at `scripts/config/syncAllTemplates.mjs`, which looks like a copy-paste error rather than a path typo. Both pre-existing.
- `bin/generateDocs.mjs` has no `#!/usr/bin/env node` shebang and did not on `main` either, so the `bin: { generateDocs }` entry does not work invoked as a bare command — only via `node <path>` as the README shows. Unchanged by this work.
- The `glob@7` → `glob@11` swap in `generateWcaComponent` is verified only manually in a clean project. It has no automated equivalent, because the module calls `main()` at import and would need a subprocess test against a fixture directory.
